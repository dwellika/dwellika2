# Dwellika

A museum-grade marketplace and social platform for artists and collectors.

Phase 1 ships the production foundation: Next.js 15 + Tailwind v4, Supabase
backend with RBAC and the complete schema for every entity in the product
spec, full authentication (email + Google/GitHub/Apple + password reset), a
global profile system, the design system, a cinematic home page with all
PRD sections, and a revamped navbar/footer.

The marketplace transaction code (cart wiring, real checkout, Stripe /
Razorpay, order processing), real reels feed, communities/competitions/
chat/notifications, AI features, admin dashboard, gamification logic,
reviews UI, dispute UI, and seller verification UI all have their database
schema in place and arrive in Phase 2.

## Quick start

```bash
# 1. Install deps
pnpm install                       # or npm install / yarn

# 2. Copy env
cp .env.example .env.local
#    then fill in NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY,
#    and SUPABASE_SERVICE_ROLE_KEY from your Supabase project's API page.

# 3. Push the database schema
supabase login
supabase link --project-ref <YOUR_PROJECT_REF>
supabase db push

# 4. Generate TypeScript types from your live schema
pnpm db:types

# 5. (Optional) Configure OAuth providers — see docs/AUTH_SETUP.md

# 6. Run
pnpm dev
```

The dev server listens on `http://localhost:3000`.

## Tech stack

- **Framework**: Next.js 15 (App Router, React 18, Server Components, Server Actions)
- **Styling**: Tailwind CSS v4 (CSS-first config, `@theme` block) + shadcn/ui
- **Backend**: Supabase (Postgres, Auth, Storage, Realtime)
- **State**: React Server Components first; Zustand + TanStack Query installed for client-side state
- **Animations**: Framer Motion, GSAP, CSS animations
- **3D (future)**: React Three Fiber + drei + three (installed; not yet used at runtime)
- **Validation**: Zod + React Hook Form

## Database

Every entity in the product spec is modeled. See [supabase/migrations](supabase/migrations/) for the SQL.

| Domain        | Tables |
| ------------- | ------ |
| Identity      | `profiles`, `artist_profiles`, `seller_profiles`, `seller_verification_docs` |
| Catalog       | `artworks`, `artwork_media`, `products`, `product_media`, `reels` |
| Social        | `follows`, `likes`, `saves`, `comments` |
| Communities   | `communities`, `community_members`, `community_posts`, `community_comments`, `polls`, `poll_options`, `poll_votes` |
| Competitions  | `competitions`, `competition_submissions`, `competition_votes`, `competition_winners` |
| Learning      | `courses`, `course_lessons`, `course_enrollments`, `workshops`, `workshop_registrations` |
| Chat          | `chats`, `chat_participants`, `chat_messages` |
| Commerce      | `addresses`, `orders`, `order_items`, `order_tracking_events`, `reviews`, `disputes`, `dispute_messages` |
| Engagement    | `notifications`, `badges`, `user_badges`, `user_levels`, `announcements`, `testimonials` |
| Operations    | `moderation_logs`, `newsletter_subscribers` |

All public tables have RLS enabled with policies that match the PRD's
access model. Helper functions `is_admin()`, `is_super_admin()`, and
`current_role()` keep policies terse.

## Roles

`profiles.role` is an enum: `super_admin | admin | artist | seller | user`.

- `/admin/*` routes require `admin` or `super_admin`
- `/artist/dashboard/*` requires `artist` (or admins)
- `/seller/dashboard/*` requires `seller` (or admins)
- `/settings`, `/checkout`, `/orders`, `/messages` require any signed-in user

Routes themselves are scaffolded in Phase 2; the guard infrastructure ships now.
